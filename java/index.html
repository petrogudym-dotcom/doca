1. JVM & Memory Management

How does Garbage Collection work in G1GC vs ZGC?

G1GC (Garbage-First) partitions the heap into equal-sized regions and performs collection concurrently and incrementally aiming for user-defined pause time targets.

ZGC (Z Garbage Collector) is a low-latency scalable collector designed to handle heaps ranging from megabytes to multiple terabytes with pause times consistently below 1ms, using colored pointers and load barriers.

What is the difference between Metaspace and PermGen?

PermGen (Permanent Generation) was part of the Java Heap until Java 7 and had a fixed maximum size, often leading to java.lang.OutOfMemoryError: PermGen space.

Metaspace replaced PermGen in Java 8. It resides in native memory (off-heap) and expands dynamically by default unless restricted by -XX:MaxMetaspaceSize.

2. Multithreading & Concurrency

What is the difference between synchronized and ReentrantLock?

synchronized is an intrinsic Java keyword managed automatically by the JVM, releasing locks when leaving the block or on exceptions.

ReentrantLock is a class from java.util.concurrent.locks offering advanced features like explicit lock/unlock, try-lock timeouts, interruptible locks, and fairness policies.

How do Virtual Threads (Project Loom) differ from platform threads?

Platform threads are 1:1 wrappers around operating system threads, making them expensive in terms of memory and context-switching overhead.

Virtual threads are lightweight threads managed directly by the JVM (M:N scheduling), allowing millions of concurrent tasks with minimal memory footprint.

3. Spring Boot & Microservices

How does Spring handle circular dependencies?

Spring resolves circular dependencies for setter or field injection using a three-level cache (singletonFactories, earlySingletonObjects, singletonObjects).

However, constructor injection circular dependencies cannot be resolved automatically and require lazy initialization via @Lazy or architectural refactoring.

What is the Saga Pattern in Microservices?

The Saga pattern manages distributed transactions by breaking them into a sequence of local transactions across services. Each local transaction updates the database and publishes an event or message to trigger the next step. If a step fails, compensating transactions are executed to roll back changes.

4. System Design & Architecture

How do you ensure zero-downtime deployment?
  • Blue-Green Deployment: Maintaining two identical production environments and switching router traffic.
  • Canary Deployment: Gradually rolling out changes to a small subset of servers before full deployment.
  • Database Migrations: Ensuring backward compatibility via multi-step schema migrations (Expand and Contract pattern).
